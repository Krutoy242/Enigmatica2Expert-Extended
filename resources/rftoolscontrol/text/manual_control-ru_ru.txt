{-------------------------------------------------------------}
{b}Введение
{n:intro}
RFTools Control — дополнение к RFTools с визуальной
системой программирования для автоматизации. Программы
могут перемещать предметы, взаимодействовать с
красным камнем, проверять запас энергии в машинах и многое другое. Есть прямая
поддержка сканера хранилища; в будущем она также даст ему
возможность автоматического изготовления.

Не пугайтесь слова «программирование». Программы
RFTools Control обычно очень просты и создаются
визуально: писать код в буквальном смысле не нужно.
Вместо этого вы перетаскиваете значки по сетке.
{-------------------------------------------------------------}
{b}Программист
{n:programmer}
{rb:programmer}
Блок «Программист» служит для создания программ. Для
работы вставьте в него карточку программы:
{ri:program_card}
{-------------------------------------------------------------}
Интерфейс может показаться сложным, но разобраться
несложно. Слева находятся все инструкции, доступные
для программ. Перетаскивайте их на большую
сетку посередине.

Помещённую на сетку инструкцию можно соединить с соседней,
нажав на её сторону. Зелёная сторона означает соединение
от этой инструкции к соседней.
У некоторых инструкций-проверок два выхода. Красный
указывает путь при отрицательном результате проверки.

На месте отсутствующего соединения автоматически вставляется инструкция Stop.
{-------------------------------------------------------------}
Каждая программа начинается с события. Инструкция события определяет,
что должно произойти для запуска. На одной карточке
может быть несколько событий, а значит, и программ.
Даже одна цепочка связанных инструкций может иметь несколько
событий, обозначающих разные точки входа в программу.

Сейчас есть семь событий: включение сигнала красного камня, его
выключение, таймер, исключение, сигнал, изготовление и возобновление изготовления.
{-------------------------------------------------------------}
У многих инструкций есть параметры. Выберите инструкцию на основной
сетке, чтобы увидеть список её параметров внизу интерфейса.
Параметры имеют типы, но многие преобразования выполняются автоматически:
например, целое число превращается в строку,
когда это необходимо.

Параметр можно задать тремя способами: постоянным
значением, переменной или функцией. Переменные хранятся
в процессоре; об этом ниже. Важная функция last
возвращает результат предыдущей инструкции.
Многие инструкции имеют результат, и этой функцией
можно его получить.
{-------------------------------------------------------------}
{b}Процессор
{n:processor}
{rb:processor}
Процессор исполняет программы. Сначала создайте
программу в блоке «Программист», затем вставьте её карточку
в процессор. Он поддерживает до 6 карточек, но
для работы потребуются дополнительные компоненты.
{-------------------------------------------------------------}
Главное — хотя бы одно ядро
процессора. Каждое ядро в одной из 16 ячеек расширения
позволяет выполнять ещё одну программу одновременно. Ядра
дороги, но даже для нескольких программ их часто нужно немного:
типичная программа работает недолго.

Есть три уровня ядер, различающиеся скоростью исполнения
и расходом энергии в RF/t.
{-------------------------------------------------------------}
Процессор хранит до 32 переменных, если установлены чипы ОЗУ.
Каждый чип добавляет 8 переменных; поддерживается максимум 4 чипа.

Чтобы программа могла использовать переменные, их нужно выделить
нужной ячейке карточки. Над ячейками есть шесть маленьких кнопок.
Нажмите соответствующую кнопку, чтобы перейти
в режим распределения. Затем отметьте нужные переменные зелёным.
Первая зелёная переменная получит индекс 0 для программ этой карточки.
Далее индексы идут по порядку. Индекс переменной в программе всегда
относителен к её распределению!

Можно выделить переменные, уже используемые другой карточкой.
Это позволяет программам разных карточек обмениваться данными.
{-------------------------------------------------------------}
У процессора также есть 24 внутренние ячейки предметов. Они
доступны всегда, но, как и переменные, выделяются
каждой карточке отдельно. Номера ячеек в программе тоже относительны:
ячейка 0 — первая ячейка, выделенная
для программы в соответствующей ячейке карточки.
{-------------------------------------------------------------}
{b}Сеть
{n:networking}
Сетевая карта и несколько узлов:
{ri:network_card}
{rb:node}
позволяют построить сеть. У процессора только шесть сторон, но сеть
расширяет возможности, открывая доступ к сторонам
всех подключённых узлов.
{-------------------------------------------------------------}
После установки сетевую карту нужно настроить
командой net setup <name> в консоли процессора.
<name> — имя сети; такое же имя указывается во всех узлах,
которые должны подключаться к ней.

Настройка карты запускает поиск всех узлов
с заданным именем канала в области 17x17x17 с
процессором в центре. Сетевая карта также нужна
для ремесленных станций, обнаруживаемых тем же сканированием.

Расширенная сетевая карта охватывает область 33x33x33 и
позволяет отправлять сообщения другим процессорам в любой точке
мира.
{-------------------------------------------------------------}
С расширенной сетевой картой можно отправлять
сообщения другим процессорам мира, если их чанки загружены.
Для этого поместите сетевой идентификатор в одну
из внутренних ячеек процессора:
{ri:network_identifier}
и привяжите его к процессору назначения правым щелчком
с приседанием. Процессору назначения сетевая карта не нужна.

Вместе с сообщением можно передать данные в виде
переменной.
{-------------------------------------------------------------}
{b}Ремесленная станция
{n:craftingstation}
{rb:craftingstation}
Ремесленная станция позволяет заказывать предметы,
изготавливаемые вашей программой на ближайшем
процессоре. Для связи со станцией процессору
нужна сетевая карта.

Изготовление иногда занимает много времени. Интерфейс
станции показывает операции, которые ещё выполняются.
{-------------------------------------------------------------}
По сути, станция показывает, для каких предметов
процессор имеет события Craft. Как только вы
закажете такой предмет, запустится соответствующая
программа. Что именно она делает — полностью ваше решение.
Чаще всего программа действительно изготавливает
нужный предмет, но может выполнять и другие действия.
Поэтому станцией можно пользоваться как пультом запуска
различных действий. Например, событие изготовления красной пыли
может просто включать обработку предметов, а
событие изготовления угля — выключать её. Решать вам.
{-------------------------------------------------------------}
{b}Крафт-карта
{n:craftingcard}
{ri:crafting_card}
Крафт-карта хранит рецепт. Часто она используется
для обычных рецептов с сеткой 3x3 и одним результатом. Интеграция
с JEI позволяет легко переносить в неё рецепты, но возможности
карты шире. Открыв её интерфейс,
вы увидите, что входных ячеек больше, чем 3x3.
Можно описывать куда более сложные рецепты, чем обычная сетка 3x3.
{-------------------------------------------------------------}
Кроме того, указанная выходная ячейка не обязана совпадать
с непосредственным результатом рецепта. Например,
вы хотите изготовить фасады Ender IO. Для них
сначала выполняется обычный рецепт, затем его результат обжигается.
Входом крафт-карты можно сделать ингредиенты сетки 3x3
для промежуточного предмета, а выходом — окончательный результат
обжига. Разумеется, такую карту должна обслуживать
программа, умеющая выполнять многоэтапное изготовление.
{-------------------------------------------------------------}
{b}Верстак
{n:workbench}
{rb:workbench}
Верстак — обычное устройство изготовления с внутренним буфером
предметов. Им можно пользоваться вручную, но главное назначение — автоматизация:
готовый результат можно извлекать трубой снизу.
Программа процессора также может напрямую подавать ингредиенты
в рецепт верстака через верхнюю сторону.

Во внутреннем буфере верстака часто хранят крафт-карты
для организации автоматического изготовления.
{-------------------------------------------------------------}
{b}Резервуар
{n:tank}
{rb:tank}
Мульти Танк хранит четыре вида жидкостей.
Рядом с процессором он предоставляет ему доступ
к четырём дополнительным жидкостным ячейкам на каждый резервуар. Их можно выделить программам,
чтобы те работали с жидкостями.

Сейчас взаимодействовать с Мульти Танком можно только
через процессор и программу, обращающуюся к жидкостям. Он служит
лишь жидкостным хранилищем с прямым доступом для процессора. Установка
рядом с узлом также не даст доступа.
{-------------------------------------------------------------}
{b}Перемещение предметов
{n:items}
Многие программы перемещают предметы. Важно помнить:
процессор не может передавать их прямо между двумя внешними инвентарями.
Предметы всегда проходят через сам процессор. Поэтому обычно
инструкции Fetch и Push используются последовательно.

Многие инструкции, работающие с обычным инвентарём,
также поддерживают систему хранения через сканер хранилища. Для этого
вставьте экранный модуль управления хранилищем RFTools в одну
из 16 ячеек расширения процессора. Затем
оставьте параметр Inventory пустым: поддерживающая этот режим инструкция
обратится к системе хранения.
{-------------------------------------------------------------}
{b}Графика
{n:graphics}
Видеокарта в процессоре даёт ограниченные возможности
векторной графики: линии, прямоугольники и текст. Также
возможно некоторое взаимодействие с изображением. Отображать его можно
двумя способами: во встроенном экранном индикаторе
в режиме Gfx или на экране RFTools с модулем векторной графики.
Взаимодействие с изображением доступно только через экран
RFTools. Для работы с графикой необходимо знать
три понятия: идентификаторы, цвета и координаты. Они описаны
на следующей странице.
{-------------------------------------------------------------}
{b}Идентификаторы
Каждая графическая операция процессора имеет идентификатор — ID.
Он позволяет изменять операцию, заменяя изображение
с этим ID, и определяет порядок отрисовки.
Графические операции выполняются в алфавитном порядке
их идентификаторов.

{b}Цвета
Цвета задаются целыми числами, удобнее всего в шестнадцатеричной записи:
$AARRGGBB. Например, $FF00FF00 — полностью
непрозрачный зелёный; $55990000 — полупрозрачный тёмно-красный.

{b}Координаты
Координаты идут от 0,0 в левом верхнем углу до 128,128 в правом нижнем.
{-------------------------------------------------------------}
{b}Основы программирования
{n:concepts}
Программа RFTools Control состоит из инструкций — Opcode,
размещённых на сетке. Они соединяются друг с другом
зелёными стрелками, а инструкции-проверки также красными, и имеют
параметры, определяющие поведение.

Подсказка инструкции в блоке «Программист» содержит
дополнительные сведения; удерживайте Shift, чтобы узнать ещё больше.
{-------------------------------------------------------------}
{b}Типы
{n:types}
Параметры и переменные имеют определённый тип:
целое число, строка и так далее. Для использования в другом качестве
нужно преобразование. Многие преобразования выполняются автоматически.
Например, если требуется строка, а последний результат — целое число,
оно автоматически превращается в строку.

Сейчас поддерживаются типы String — строка, Integer — целое, Float — дробное число,
Boolean — логическое значение, Side — сторона процессора или подключённого
узла, Inventory — инвентарь рядом с процессором или
подключённым узлом, при необходимости со стороной доступа,
Item — стопка предметов, и Exception — исключение.
{-------------------------------------------------------------}
{b}Параметры
{n:parameters}
Как уже говорилось, у инструкции может быть несколько параметров,
управляющих её работой. Каждый параметр имеет тип. Многие
необязательны — это указано в подсказке.

Параметр может быть постоянным значением, ссылкой на
переменную или функцией. Откройте редактор параметров
кнопкой «...» в блоке «Программист» и выберите один из вариантов
кнопками сверху.

Список доступных функций зависит от типа параметра.
Для некоторых типов функции пока не определены.
{-------------------------------------------------------------}
{b}Переменные
{n:variables}
Процессор хранит до 32 переменных. Как и параметры, они имеют тип.
Обязательно выделите переменные нужной ячейке
карточки. Все программы одной карточки автоматически
используют общий набор этих переменных.

Переменные можно совместно использовать и между карточками:
одна переменная может быть выделена нескольким карточкам.

Программа обращается к переменным по относительному индексу.
Переменная 0 означает первую переменную, выделенную
данной карточке.
{-------------------------------------------------------------}
{b}События
{n:events}
Программы RFTools Control управляются событиями:
они запускаются только при определённом событии. Это может быть импульс
красного камня, таймер, заказ предмета и многое другое.

У большинства событий есть параметры условий срабатывания.

У каждой цепочки связанных инструкций на карточке должно быть хотя бы
одно событие, иначе она никогда не запустится. К одной цепочке
можно подключить несколько событий.

Сработавшее событие выполняется на свободном ядре. Если свободных ядер
нет, событие ставится в очередь. Исключение — таймер:
его событие отбрасывается, если свободного ядра нет.
{-------------------------------------------------------------}
{b}Типы инструкций
{n:opcodes}
Доступны следующие типы инструкций:
  * Events: события; каждой программе нужно хотя бы одно
  * Operation: обычные операции
  * Evaluate: вычисление или проверка,
    сохраняющая результат для использования следующей
    инструкцией
  * Test: логическая проверка с переходом
    в зависимости от результата; поэтому у неё
    два выхода — зелёный и красный
  * Wire: единственная инструкция-провод, соединяющая
    инструкции, которые не находятся рядом
{-------------------------------------------------------------}
{b}Токены
{n:tokens}
{ri:token}

Токены — предметы, предназначенные исключительно для хранения
информации. Одна программа может записать в токен любые данные,
а другая — прочитать их.
Токен можно перемещать как обычный предмет,
передавая вместе с ним информацию куда угодно.
{-------------------------------------------------------------}
{b}Параллельное выполнение
{n:concurrency}
Несколько ядер процессора позволяют нескольким программам
работать одновременно. Но здесь есть тонкости. Прежде всего
правильно распределите ячейки и переменные, если
программы не должны делиться данными. Это простой случай.

Иногда данные всё же должны быть общими. Например, одна
программа кладёт предметы во внутренние ячейки, а другая
забирает их. Для безопасной работы могут потребоваться
блокировки. Блокировка имеет имя и действует на весь процессор,
то есть на все его программы. Удерживать блокировку с определённым
именем может лишь одна программа. Остальные ждут, пока она
освободится. Всегда освобождайте взятые блокировки! Если забыли,
команда reset сбросит процессор и всё очистит.
{-------------------------------------------------------------}
Ещё одна проблема — не дать одной программе занять
все ядра. Например, программа работает некоторое время
и запускается по сигналу красного камня. Если быстро
подать два сигнала, могут одновременно запуститься несколько экземпляров
этой программы, если есть свободные ядра.

Иногда это допустимо, но часто нужен только один
работающий экземпляр. Для этого у каждого события есть
параметр Single. При значении
True событие срабатывает один раз и блокируется, пока
запущенная им программа не завершится.
{-------------------------------------------------------------}
Другой способ управления параллельностью — режим Exclusive
в интерфейсе процессора. Если он включён,
программы карточки X могут работать только на ядре X.
Таким образом, каждое ядро выделено исключительно одной карточке.

Это также полезно, когда в процессоре установлены
ядра низкого и высокого уровня. Режим Exclusive позволяет
гарантировать, что требовательные программы выполняются только на ядре
высокого уровня.
{-------------------------------------------------------------}
{b}Отладка
{n:debugging}
Вы будете допускать ошибки. Повторяйте за мной: ошибки неизбежны! Как
их исправлять? Есть несколько способов. Инструкция Log
выводит сообщения в консоль: как простой текст,
так и содержимое переменных.

Для более сложных случаев есть встроенный
отладчик. Откройте консоль процессора и введите:
    db debug

Это остановит все работающие программы и позволит
выполнять выбранные программы пошагово — по одной инструкции
за раз.
{-------------------------------------------------------------}
Чтобы увидеть текущее положение программы, выполните:
    db info

Чтобы сделать один шаг программы на ядре 0, например, введите:
    db s 0

Текущая инструкция выполнится, затем отобразится следующая,
ожидающая вашего запуска.
Последний результат можно проверить командой:
    db last 0

Или используйте db last для последних результатов всех текущих программ.
{-------------------------------------------------------------}
Во время пошагового выполнения можно также
просматривать переменные кнопкой «...» слева
и изменять их.

Чтобы продолжить все программы, выполните:
    db resume
{-------------------------------------------------------------}
{b}Обмен программами
{n:sharing}
Блок «Программист» поддерживает буфер обмена. Выделите инструкции,
нажмите Ctrl-C, и выбранная часть сетки скопируется в буфер как
JSON, которым можно поделиться в интернете. Программу из
буфера можно вставить сочетанием Ctrl-V. Если она достаточно мала,
выберите участок сетки, щёлкнув по ячейке,
где должна оказаться верхняя левая инструкция. Если
ничего не выбрано, вставка начнётся с верхнего левого угла. Содержимое
буфера объединяется с тем, что уже находится на сетке.

Действие всегда можно отменить сочетанием Ctrl-Z.

Ctrl-A выделяет всю сетку; щелчок с Ctrl —
одну инструкцию, а двойной щелчок с Ctrl — цепочку.
{-------------------------------------------------------------}
